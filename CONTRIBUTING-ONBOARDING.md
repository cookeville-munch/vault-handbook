# New Contributor Onboarding Guide

Welcome to the Kink Handbook! This guide will help you make your first contribution in under 10 minutes.

## Quick Start (5 Minutes)

### 1. Fork & Clone
```bash
# Fork the repository on GitHub, then:
git clone https://github.com/YOUR-USERNAME/vault-handbook.git
cd vault-handbook
git remote add upstream https://github.com/elijah/vault-handbook.git
```

### 2. Create Your Feature Branch
```bash
git checkout -b feature/your-module-name upstream/master
```

### 3. Generate Module Template
```bash
./scripts/create_new_module.sh 12 "advanced-taxi-play" "Your Name" "intermediate"
```
This creates:
- `content/modules/12-advanced-taxi-play/`
- `content/modules/12-advanced-taxi-play/12-advanced-taxi-play.md`
- Updates navigation automatically

### 4. Add Your Content
Edit the generated file with your expertise. Replace placeholder sections with substantive content.

### 5. Validate Locally
```bash
# Update navigation
./update_navigation.sh

# Validate all modules
python3 scripts/validation/validate_structure.py --modules-dir content/modules

# Check for link issues (requires Node.js)
npx markdown-link-check content/modules/**/*.md --config .markdown-link-check.json
```

### 6. Commit & Push
```bash
git add .
git commit -m "feat: add advanced taxi-play module"
git push origin feature/your-module-name
```

### 7. Open Pull Request
Go to GitHub and open a PR from your branch to `upstream/master`.

## What Makes a Great Contribution

### Structure Requirements
- ✅ Follows existing module format (H1, Overview, Core Principles, Techniques, Case Studies, Safety Protocols)
- ✅ Complete frontmatter: `title`, `date`, `author`, `difficulty-level`
- ✅ Proper naming: `NN-descriptive-name.md` in `NN-descriptive-name/` directory
- ✅ Minimum 500 characters of content per file

### Content Quality
- 🎯 **Substantive**: Original expertise, not just placeholders
- 🔗 **Connected**: References related safety protocols and existing modules
- 🛡️ **Safety-first**: Includes risk mitigation, contraindications, emergency procedures
- 📚 **Educational**: Clear learning progression with assessment criteria

### Accessibility
- ♿ Use descriptive headings and alt text for screen readers
- 🎨 Ensure color contrast in any diagrams
- 📱 Test mobile readability

## Navigation Updates

The `update_navigation.sh` script automatically:
- Updates `README.md` (Advanced Topics section)
- Updates `new_toc.md` (Module Navigation section)
- Maintains alphabetical ordering

**Run it after creating any new module.**

## CI Validation Pipeline

Your PR will automatically run:
1. **Markdown & YAML linting**
2. **Accessibility audit** (WCAG 2.1 AA)
3. **Mermaid diagram validation**
4. **Link checking**
5. **Module structure validation** (foundational modules 01-03)
6. **Documentation build**

All checks must pass before merge.

## Common Pitfalls to Avoid

| Pitfall | Solution |
|---------|----------|
| Missing frontmatter fields | Use the template generated by `create_new_module.sh` |
| Placeholder content only | Replace ALL `[Insert...]` sections with real content |
| Broken internal links | Run `npx markdown-link-check` locally |
| Inadequate safety content | Include 3+ safety concepts (emergency, contraindication, warning, etc.) |
| Wrong naming convention | Must be `NN-description.md` in `NN-description/` directory |

## Getting Help
